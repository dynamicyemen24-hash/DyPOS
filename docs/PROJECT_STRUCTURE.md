# هيكلة المشروع — لماذا يتفرّع `DyPOS/` عن `POS/` وهل يجب دمجهما؟

> هذا المستند يجيب رسميًا عن أكثر سؤال يسبب ارتباكًا في المستودع، ويُثبت
> القاعدة: **الشفرة المصدرية شيء، وناتج البناء شيء آخر — لا يُدمجان.**

## 1️⃣ خريطة المستودع `D:\SulationDy\DyPOS\`

| المجلد | الدور | مصدر أم ناتج؟ |
|--------|-------|---------------|
| `POS/` | مشروع الواجهة المصدرية (Vite + Vue 3 + Tailwind 3 + Vitest) — **مكان التعديل** | 🔧 مصدر |
| `DyPOS/public/pos/` | ناتج البناء الثابت (index.html + assets + sw.js + workbox + الأيقونات) | 📦 ناتج |
| `DyPOS/www/pos.html` | نسخة `index.html` قابلة للنشر عبر `www` في Frappe | 📦 ناتج |
| `imag/` | أصول الهوية الأصلية (الشعار، الأيقونات، صورة الدخول `smart-ports-og.jpg`) | 🗄️ أصول |
| `pos_next/` | مشروع الجيل القادم (واجهة + خلفية) — منصة موازية قيد التطوير | 🔧 مصدر |
| `cf-deploy/` | لقطات نشر (تتضمن نسخًا من ناتج POS وبعض ملفات الباك-إند) | 📦 نسخة |
| `.github/workflows/` | CI: اختبارات + بناء + نشر | ⚙️ أدوات |

## 2️⃣ السلسلة الفعلية للبناء (من المصدر إلى النشر)

```text
تحرير الكود ← POS/src/*
        │  (npm run build)
        ▼
POS/vite.config.js:
   outDir  = ../DyPOS/public/pos   ← ناتج PWA الكامل
   indexHtmlPath = ../DyPOS/www/pos.html  ← مدخل www لـ Frappe
        │
        ▼
الإخراج: DyPOS/public/pos/{index.html, assets/*, sw.js, workbox-*…}
```

- `base=/assets/DyPOS/pos/` في البناء يعني أن المسار **المُصرَّح به** في Frappe هو
  `/assets/DyPOS/pos/` — أي أن اسم مجلد الناتج `DyPOS` ليس عشوائيًا بل يطابق
  اسم التطبيق/الموقع المُخدَّم. تغييره يستلزم تغييرًا منسقًا في البناء + CI + نشر أحدث.
- `DyPOS/public/pos/` و `DyPOS/www/` **مستثنيان من git** مسبقًا في `.gitignore` —
  أي أنهما ناتج تشغيلي **لا** يُحفظ في التحكم بالنسخ.

## 3️⃣ لماذا لا يُدمج `DyPOS/` في `POS/`؟ (القرار الرسمي)

| السبب | الشرح |
|-------|-------|
| تناقض الدور | `POS/` كود مكتوب بخط الإنسان؛ `DyPOS/` كود مُصغَّر يولَّد آليًا. دمجهما يلوّث المصدر بـ 400+KB من ملفات قديمة تتعارض عند كل بناء |
| هندسة النشر | الناتج يجب أن يسكن مسارًا محددًا يشير إليه Frappe (`/assets/DyPOS/pos/`) والـ PWA precache. نقله تبديل مسار = كسر النشر القائم وعملاء متصلين |
| نظافة git | الناتج داخل التحكم بالنسخ = تفجير تاريخ التغييرات (+آلاف الأسطر المُصغَّرة) وتعارضات دمج وهمية |
| الاسترجاع | فصل المصدر عن الناتج يجعل "الرجوع بإصدار" ممكنًا: أعد البناء من أي التزام مصدري ونشر نظيفًا |

**الخلاصة**: الفصل **صحيح هندسيًا** والاسم المتشابه (POS ⇄ DyPOS) هو مصدر الالتباس فقط.
