## الرؤية

> **V1**: نقطة بيع تعمل (وتعمل دون اتصال).
> **V2**: محور أعمال موصول — امتثال حكومي، شاشة تحليل، مطبخ رقمي، دفعات رقمية، وبنية لا تنهار عند الانقطاع أو النمو بعدّادات متعددة.

## المحور 1 — الفاتورة الإلكترونية السعودية (ZATCA) — الأولوية القصوى

**الهدف**: إخراج فواتير متوافقة قانونيًا مع هئية الزكاة والضريبة والجمارك، شمولاً للمبيعات دون اتصال.

**الأسس الجاهزة**: `einvoice_framework` في `posSettings`، جداول `zatca_settings` / `zatca_registration` / `zatca_audit_trail` في `db.js`.

**التسليمات**:
1. تفعيل `einvoice_framework="zatca"` مع موجّه ادعان (Onboarding) يدعم بيانات اعتماد محيط/Fatooh.
2. مولّد **SDF (XML)** + **OFS (بي دي إف مع QR TUVA)** لكل فاتورة — بما فيها دون اتصال (prefix خاص + علامة `simplified`).
3. مزامنة بيت-محور (asynchronous: queue + retry + state machine).
4. شجرة تدقيق ثابتة (hashing) على `zatca_audit_trail` + قاعدة «آخر 5 فواتير» لانقطاع مؤقت.
5. لوحة حالة زاتكا: رقم CR، تاريخ انتهاء، توازن الفواتير المعلّقة.

**معايير النجاح**: ≥95% من الفواتير المزمّنة خلال 24 ساعة؛ صفر فواتير بدون QR.

---

## المحور 2 — شاشة التحليل والتقارير (أعلى قيمة مدركة)

**الهدف**: تحويل قرارات الإدارة إلى بيانات على الشاشة.

1. صفحة `Dashboard.vue` جديدة.
2. تقارير سعرية: Z وX وتقرير المناوبة والإغلاق اليومي (إعادة بناء من مصدر واحد بدل تشتت `printEod.js`).
3. تبويبات: مبيعات عبر الوقت، أفضل المنتجات، متوسط الفاتورة، مقارنة نوبة/نوبة.
4. تصدير Excel/CSV/PDF وطباعة عبر QZ.
5. Route lazy + قيود أذونات (`usePermissions.js`).

**ملاحظة بنية**: التقطيع والتحميل الكسول لأحزمة `POSSale`/`index` أساس إلزامي لأي صفحة جديدة.

**معايير النجاح**: فتح لوحة التحليل خلال <3 ثوانٍ؛ تصميم قرار قرار/نوبة لمدير الفرع.

---

## المحور 3 — شاشة المطبخ الموصولة (KDS) + أدوار المصنع

1. `KitchenDisplay.vue`: بطاقات أوامر حية عبر `initSocket()`؛ تلوين مهلة (جاهز/طويل)؛ تمييز عناصر per-station.
2. طباعة أوامر مطبخ تلقائية عند السداد (قائمة طباعة منفصلة).
3. أدوار «كاشير/مطبخ/مدير» عبر `usePermissions.js` مع فرض على مستوى الروابط.

**معايير النجاح**: زمن عرض أمر المطبخ <1 ثانية بعد الدفع؛ إمكانية تفعيل/إيقاف شاشة المطبخ من POS Settings.

---

## المحور 4 — الدفعات الرقمية والدرج النقدي

1. واجهة بوابة دفع (Tap/PayTabs/Mada أو KNET) عبر خيار `payment_gateway` في `posSettings`؛ حالة دفع/فشل/استرداد + صف دفع في قائمة دون اتصال.
2. درج نقدي (RJ12 عبر Web/Serial APIs) عند X/Z/الفتح.
3. **سند إيداع/سحب أموال** (Tender Drop) بسياق محاسبة واضح — البنية سياقية موجودة أصلًا في `invoices.py:2220`.

**معايير النجاح**: معاملة دفع رقمية كاملة مع حالة معلّقة/مؤكدة؛ صفر فواتير بدون أثر تسوية.

---

## المحور 5 — Offline 2.0 (حماية البيانات والاستعادة)

1. حل تعارض مزامنة: آخر تعديل يفوز معتماً + تسمية نسخة احتياطية لكل فواتير دون حل تلقائي.
2. نسخ احتياطي/استعادة كامل لـ IndexedDB (تصدير/استيراد JSON موقّع + ضغط).
3. فحوص سلامة تشغيل-كثافة لـ `db.invoice_queue`؛ احتواء الانتفاخ بالـ `logger.js`.
4. مزامنة خلفية (Background Sync) بدون فتح التطبيق.

**معايير النجاح**: صفر فواتير مفقودة بعد انقطاع قسري؛ اختبار استعادة نسخة كامل.

---

## المحور 6 — الموثوقية والترميز (اختبارات + مراقبة + أمان)

أكبر دين فني: **لا اختبارات تحريرية حاليًا** رغم `vitest` و`@vue/test-utils` المثبّتين.

1. تغطية وحدة للوسائل الحرجة (`posCart` / `posSync` / `itemSearch` + أهم الـ composables)، هدف ≥80% على الحرجة.
2. اختبارات E2E (Playwright) للسيلانات الحرجة: اشتراك → بيع → سداد → إغلاق → مزامنة دون اتصال.
3. ضبط الأداء: budget build (حد تحذير `chunkSizeWarningLimit`)، تقطيع `POSSale`/`index` + lazy.
4. تدقيق أمان: مراجعة `_headers` CSP الحالية، مدخل `csrf.js`.
5. TS تدريجي للملفات الحرجة (عند حاجة فعلية لإعادة هيكلة).

**معايير النجاح**: تسكير مجلد في PR غير مسموح به بدون اختبارات للملفات الحرجة؛ عدد الأخطاء الصامتة (console.error) في السيلانات الحرجة = 0.

## خارطة التنفيذ (3 مراحل)

| المرحلة | النطاق | الأثر | الأولوية |
|---|---|---|---|
| **ألف — الامتثال والدفع** | زاتكا + بوابة دفع + درج + Tender Drop | امتثال قانوني + إيراد | الأعلى |
| **باء — القيمة المدركة** | لوحة تحليل + تقارير X/Z (بالتوازي مع باء تُفتح سريعًا) | رضا الإدارة/الأصحاب | منخفض/متوسط |
| **جيم — التحول** | KDS + أدوار + تقطيع الحِزم + زاتكا دون اتصال الشامل | توسع بعدّادات وفروع | متوسط/عالٍ |

> ملاحظة: يُنصح بفتح **باء** كسرد/مُشاهد فوري مع مواصلة **ألف** — الفارق في الثقة المدركة سريع وغير مكلف.

## منهجية إصدار ثابت لكل محور

1. تنفيذ وتنظيف (biome).
2. اختبارات للجزء الجديد.
3. `npm run build` (بدون تجاوز budget).
4. مزامنة staging مع حفظ `_redirects`/`_headers`.
5. `wrangler pages deploy` + تحقق 200 للإنتاج.
